# Account units, close events, and bounded histories

Account creation accepts exact decimal **percentage points**: `"1"` means 1%, `"0.25"` means 0.25%, and `"100"` means 100%. Tax and earnings reserves must be nonnegative and total at most 100%. Validation runs in the facade and the SQLite write boundary before creating any account or default level. Distribution-policy fields continue to use explicitly named fractions between 0 and 1; their existing contract is unchanged.

The account-units migration marks existing tax values as `legacy`; the SQLite adapter preserves their historical interpretation using Decimal arithmetic. Thus an existing tax value of `1` continues to mean 100%, while a newly created account containing `1` means 1%. Domain reads always return percentage points. There is no magnitude-based guessing on newly written values. Invalid negative or out-of-range legacy values fail validation and require deliberate owner repair; they are never silently clamped. A downgrade refuses to discard explicit units while new-format accounts exist.

Backup format 3 records the units. Complete format-2 backups from the immediately preceding schema can still be restored, preserving historical tax liability. Format-3 JSON must include the units. Unknown units and invalid percentages are rejected before restore writes begin. Encrypted backups use the same inner envelope.

Close events calculate stop distance in the trade direction, so a short entry of 100 and stop of 110 has the same risk distance as a long entry of 100 and stop of 90. Arithmetic errors propagate to the surrounding transaction. The event's R denominator is the **remaining bracket risk at close**, because original risk is not persisted; a stop already protecting break-even or profit produces zero remaining risk. This is not an original-risk performance metric. Leveling currently uses its persisted performance snapshot, not this R field.

Automatic profit distribution has one authoritative facade workflow, based on the persisted close state, within the close transaction. The unused `EventDistributionService` was removed. A regression repeats the original broker close observation and verifies that receipts, balances, and transactions do not change.

Trade, transaction, and distribution-history tools filter and page inside SQLite. Counts and page contents share a database read transaction. Trade and transaction order is ascending `(created_at, id)`; distribution receipts use descending `(distribution_date, id)`. Symbols are matched literally and case-insensitively. Account scope, active/closed status, inclusive transaction dates, soft deletion, and tax exclusions apply before pagination. Reconciliation uses an exclusive UUID cursor and a bounded batch. The existing `{items, total, next_offset}` envelope remains unchanged.

These queries bound object materialization and use account/order indexes. Exact totals and deep offset scans still require work proportional to matching index entries; this is not a constant-time guarantee. Keyset paging for arbitrary history browsing remains a possible future API extension.

`core/tests/history_contracts.rs` checks deterministic paging, scope, date boundaries, distribution receipts, batch cursors, and rejection of unbounded requests. It corrupts an off-page trade to prove that a small page does not decode the full trade history. `db-sqlite/tests/account_percentages.rs` covers percentage boundaries, migration, reopen, old/new backup compatibility, malformed restore rejection, and refusal of a lossy downgrade.

`core/tests/account_tax_units.rs` checks actual closed-trade tax liabilities at 0.25%, 1%, 2%, and 100%. The process test in `service/tests/e2e/history.rs` compares MCP and HTTP pages, account isolation, invalid reserve rejection, and persistence across service restarts. These named financial and protocol contracts are required by the offline assurance levels. The mutation gate deliberately breaks percentage validation, percentage conversion, short risk, and the SQL page bound and requires each selected test to detect the defect.
